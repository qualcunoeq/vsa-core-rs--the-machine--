# Stage 233 — sealed learning curve from provenance-derived modules

This is the first program-level learning curve after source module boundaries
were derived from provenance rather than a predeclared domain list. A corpus
of 1,000 raw technical reports was permanently partitioned before execution:
600 development, 200 validation, and 200 sealed holdout cases.

The baseline receives no acquired modules. The post-acquisition run receives
only six provenance-derived catalogs in a curriculum-memory clone. The sealed
partition is not used to select or modify a source module.

Results:

* source corpus: 3 documents, 21 records, 6 derived modules;
* 180/180 independent source-validation cases exact and replayed;
* malformed source corpus rejected before acquisition;
* 120/120 source-memory gaps replayed across 6 exact clusters;
* 7/7 plans replayed, with 6 promotable plans and 1 broad distractor refused;
* baseline authorizations: 0/600 supported cases;
* post-acquisition: 1,000/1,000 terminal decisions exact;
* post-acquisition: 600/600 supported cases authorized, 200/200 unresolved
  cases preserved, and 200/200 unsupported cases refused;
* sealed holdout: 200/200 exact decisions and 120/120 supported answers;
* 6/6 clone catalogs uniquely retrieved and replay-verified;
* 6,600/6,600 emitted frontend/downstream receipts replayed and
  tamper-rejected;
* parent memory and curriculum manifest unchanged;
* zero false authorizations, false denials, and live mutations.

The source records are bounded repository transcriptions and the run remains
shadow-only. This demonstrates autonomous source-derived transfer on a sealed
independent partition, not unrestricted web-scale education.
